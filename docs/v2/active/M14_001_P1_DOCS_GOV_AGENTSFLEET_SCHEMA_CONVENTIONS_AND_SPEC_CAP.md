## Overview

**Goal (testable):** `test_conventions_carry_naming_rules` — after `orly update`, a consumer selecting `product.agentsfleet` receives schema conventions carrying the nine rules, the counter table, the runtime SQL and migrator sections, and no Zig or `schema/embed.zig` text; a spec of up to 500 lines passes the template gate.
**Problem:** the agentsfleet product section of `docs/SCHEMA_CONVENTIONS.md` says nothing about which Postgres schema owns a table, how keys, counters and timestamps are named, or how runtime SQL is checked, so tables drifted into one schema with duplicated and unread columns. It still instructs Zig constants, `std.time.milliTimestamp()` and `schema/embed.zig`, all retired. The operating model names entities `core.fleet_*`, a schema agentsfleet is dissolving. The 320-line spec cap forces splitting specs the owner wants whole.
**Solution summary:** replace the product section of the conventions with the signed-off rules; change the operating model's entity line to `fleet.*`; raise the spec cap to 500 in the audit and the template text. Run the governance procedure and release it so consumers pick it up.
